# CLAUDE.md — facturo (клиент)

Технические правила фронтенда Facturo. Идея и фазы — в `PLAN.md`.

Эти правила одинаково обязательны для человека и для ИИ-ассистента. Если правило
мешает — меняем правило в этом файле, а не обходим его в коде.

---

## Команды

```bash
npm run dev             # разработка
npm run verify          # format → lint → lint:fsd → typecheck → test → build
npm run lint:fsd        # структурные проверки FSD (steiger)
npm run api:generate    # сгенерировать слой данных из openapi.json сервера
```

Перед коммитом — `npm run verify`. CI делает ровно это же.

Чтобы обновить API-слой: в `facturo-server` выполнить `npm run openapi:export`,
затем здесь `npm run api:generate`. Файлы в `src/shared/api/generated/` руками не
правятся и в git не попадают.

## Стек

| Слой | Технология | Зачем именно она |
|---|---|---|
| Каркас | Next.js 16 (App Router) | SSR для SEO, роутинг, метаданные |
| Язык | TypeScript 6.0, strict | без `any` |
| Стили | Tailwind CSS v4 | токены в `globals.css`, без отдельных CSS-файлов |
| Данные | Redux Toolkit + **RTK Query** | один кеш и официальная генерация из OpenAPI |
| Формы | react-hook-form + zod | валидация одной схемой |
| i18n | next-intl | ro/ru, сообщения в JSON |
| Анимации | framer-motion | с `MotionConfig reducedMotion="user"` |
| Мониторинг | `@sentry/nextjs` | через `instrumentation.ts` |
| Тесты | Vitest + Testing Library | |
| Структура | steiger + правила импортов в eslint | FSD проверяется линтером |

### Почему RTK Query, а не TanStack Query

Единственная причина — **`@rtk-query/codegen-openapi`**. Сервер публикует
OpenAPI-документ; генератор превращает его в полностью типизированные хуки для
каждого эндпоинта. Никто не пишет руками ни одного `fetch` и не копирует руками
ни одного типа ответа. Это убирает целый класс расхождений между клиентом и
сервером и заметно сокращает объём кода, который приходится писать и вычитывать
на каждую новую ручку.

У TanStack Query официальной генерации нет, только сторонние решения. При прочих
равных он был бы не хуже; здесь прочие равные не выполняются.

**Следствие:** второго кеша в проекте быть не должно. Всё, что приходит с
сервера, живёт в RTK Query. `useState` — для состояния экрана, не для данных.

## Архитектура: Feature-Sliced Design

```
src/
├── app/         роуты Next.js, провайдеры, layout, метаданные, globals.css
├── views/       страницы целиком (то, что FSD зовёт pages)
├── widgets/     самостоятельные блоки страницы
├── features/    действия пользователя (создать, отправить, войти)
├── entities/    бизнес-сущности (счёт, контрагент, компания)
└── shared/      переиспользуемое без привязки к домену
```

### Главное правило импортов

**Слой импортирует только из слоёв ниже себя. Никогда наоборот и никогда вбок.**

```
app → views → widgets → features → entities → shared
```

`entities/invoice` **не может** импортировать `features/invoice-create`.
`features/*` **не могут** импортировать друг друга напрямую. `shared/*` не знает
ни о чём, кроме себя, — с единственным исключением: сегменты внутри `shared`
могут использовать друг друга (`ui` форматирует через `lib`).

Нарушение этого правила — единственная причина, по которой FSD-проекты
превращаются в кашу. Поэтому оно **проверяется линтером**, а не памятью: см.
`restrictedImportsFor` в `eslint.config.mjs`. Правило работает по тексту импорта,
а не по резолверу модулей, — поэтому любой межслойный импорт идёт через алиас
`@/`.

### Публичный API слайса

Наружу слайс отдаёт только то, что перечислено в его `index.ts`:

```ts
// правильно
import { InvoiceStatusBadge } from '@/entities/invoice';

// запрещено, линтер это ловит
import { InvoiceStatusBadge } from '@/entities/invoice/ui/invoice-status-badge';
```

Внутри своего слайса — относительные пути, любая глубина.

### Структура слайса

```
features/invoice-create/
├── api/          запросы к серверу (обычно реэкспорт сгенерированных хуков)
├── model/        схемы, типы, чистая логика
├── ui/           компоненты
└── index.ts      публичный API слайса
```

### Что где лежит

| Вопрос | Слой |
|---|---|
| Кнопка, инпут, иконка | `shared/ui` |
| Формат денег, дат, телефона | `shared/lib` |
| Карточка счёта, бейдж статуса | `entities/invoice` |
| Форма создания счёта | `features/invoice-create` |
| Шапка приложения, таблица счетов | `widgets/*` |
| Страница «Счета» целиком | `views/invoices-list` |
| Роут `/invoices` и метаданные | `app/[locale]/(workspace)/invoices` |

## Дизайн-система

### Токены вместо магических значений

Все цвета, радиусы и тени объявлены один раз в `src/app/globals.css` в блоке
`@theme` и используются только через них. Хардкод `#2b41d8` или
`border-radius: 12px` в компоненте запрещён — при смене бренда придётся править
сотню файлов.

```
--color-brand-50 … --color-brand-900   одна шкала бренда, 10 ступеней
--color-success-* --color-warning-* --color-danger-*
--color-ink --color-ink-muted --color-line --color-surface --color-surface-sunken
--radius-control   кнопки, инпуты
--radius-card      карточки, модалки
--shadow-card --shadow-raised --shadow-button
--size-control --size-control-lg
```

### Типографика

- Один шрифт на весь проект — Inter, подключён через `next/font`, который
  самохостит файлы при сборке. В рантайме к Google Fonts обращений нет.
- Подключены `latin`, `latin-ext` (румынская диакритика ă â î ș ț) и `cyrillic`.
  Шрифт без одного из них показывает половине аудитории квадраты.
- Заголовки — плотный трекинг (`-0.02em`), вес 700–800.
- Основной текст 15–16px. Мельче нельзя: значительная часть аудитории старше 40 и
  читает счета с телефона.

### Размеры и попадание пальцем

- Минимальная высота интерактивного элемента — **44px** (`--size-control`).
- **56px** (`--size-control-lg`) — для экранов, которыми пользуются стоя одной
  рукой: мобильная форма счёта.
- Отступы кратны 4px, между соседними кнопками минимум 8px.

### Компоненты

- Примитивы живут в `shared/ui`: `Button`, `Input`, `Field`, `Card`, `Badge`,
  `Skeleton`, `EmptyState`, `ErrorState`, `Logo`.
- Варианты кнопки фиксированы: `primary`, `secondary`, `ghost`, `danger`,
  `success`. Новый вариант добавляется в примитив, а не классами на месте вызова.
- Иконки — свой набор SVG в одном файле, наследующий `currentColor`. Библиотека
  иконок ради десятка глифов не нужна.

### Четыре состояния у каждого экрана

Не только «всё хорошо», а все четыре:

1. **Загрузка** — скелетон, а не пустота и не спиннер на весь экран.
2. **Пусто** — `EmptyState` с объяснением и кнопкой следующего шага.
3. **Ошибка** — человеческий текст, а не код ответа.
4. **Готово** — собственно данные.

### Анимации

- Только лёгкие: 150–300 мс, вход через прозрачность и сдвиг на 8–12px.
- Списки — каскадом с задержкой ~45 мс между элементами.
- Всё приложение обёрнуто в `MotionConfig reducedMotion="user"`: у кого в системе
  включено «уменьшить движение», анимации выключаются (WCAG 2.3.3).
- Анимация не задерживает действие. Пользователь не ждёт красоту.

### Мобильный подход

Проектировать сначала под 400px, потом расширять. Аудитория заходит с телефона.
Горизонтальной прокрутки не должно быть нигде, кроме таблиц, и те — в собственном
контейнере с `overflow-x: auto`.

## Правила написания кода

### TypeScript

- **`any` запрещён.** Неизвестный тип — `unknown` и сужение через проверки.
- `@ts-ignore` запрещён; `@ts-expect-error` — только с объяснением рядом.
- Типы данных с сервера берутся из сгенерированного слоя. Ручные копии в
  `entities/*/model/types.ts` — это словарь домена, а не дубликат контракта.
- **Деньги приходят строкой** (`"25.00"`) и остаются строкой до форматирования.
  Число уже потеряло копейки.

### Именование

- Файлы `kebab-case.tsx`, компоненты внутри — `PascalCase`.
- Хуки — `use-*.ts`.
- Булевы: `isLoading`, `hasSession`, `canEdit`.
- Никаких сокращений: `invoice`, а не `inv`.
- Английский в коде. Русский и румынский — только в `messages/*.json`.

### Комментарии

Комментарий объясняет **почему**, а не **что**. `///` — описание модуля или
публичной функции, `//` — пояснение строки.

### Размеры

Компонент до ~200 строк, файл до ~300. Ориентиры, а не лимиты; превышение вдвое
требует обоснования.

### Запрещено

- `any`, `@ts-ignore` без объяснения
- логика в `app/**/page.tsx` — роут только собирает view и задаёт метаданные
- прямой импорт вглубь чужого слайса мимо `index.ts`
- второй кеш серверных данных рядом с RTK Query
- хардкод цвета, радиуса, тени
- чтение часов (`Date.now()`, `new Date()`) во время рендера компонента
- коммит в `main` без прохождения CI

## i18n и SEO

Без этого мультиязычный сайт не индексируется нормально.

- **Язык в URL, а не в cookie.** `/ro` и `/ru` — отдельные адресуемые страницы.
  Контент, переключаемый cookie на одном URL, поисковик засчитает как одну версию.
- **Полный кластер hreflang** (`ro`, `ru`, `x-default`) на всех вариантах,
  взаимно согласованный.
- **Canonical** на каждой публичной странице.
- **JSON-LD** (`Organization`, `SoftwareApplication`, `FAQPage`) — это то, что
  ИИ-поисковики читают раньше текста.
- **FAQ на странице обязан совпадать** с разметкой `FAQPage`. Невидимая разметка
  — нарушение.
- `sitemap.xml` с `alternates`, `robots.txt`, `llms.txt` для ИИ-агентов.
- OG-изображения 1200×630 под каждый язык: ссылки шлют в WhatsApp и Viber, и
  голая ссылка без превью выглядит как спам.
- **Приватные разделы** закрыты в `robots.txt` **и** помечены `noindex`.
  `Disallow` сам по себе не гарантирует отсутствия в индексе.
- **Региональный тег в форматировании:** `ro-MD` и `ru-MD`, не `ro-RO` и
  `ru-RU`. Только так MDL отображается как «L», а не как «MDL». Форматирование
  идёт через `shared/lib/format.ts`, руками `Intl` нигде не создаётся.
- Оба языка заполняются в одном коммите. Ключ, существующий только в одном
  файле, — это пустая строка у половины пользователей.

## Юридическое

До первого реального клиента нужны Условия использования и Политика
конфиденциальности: обрабатываются персональные данные (телефоны, имена, адреса).

Политика отвечает на: какие данные собираются по каждой категории; зачем; с кем
делятся (провайдер платежей, хостинг БД, мониторинг ошибок — больше ни с кем);
какие cookie (только функциональные: сессия и язык, поэтому баннер согласия не
нужен, и это стоит написать прямо); сколько хранятся и как удалить аккаунт; права
пользователя и срок ответа.

Условия отвечают на: что такое сервис и чем он **не** является; ответственность
за сохранность пароля; что запрещено; честно про доступность без обещаний 100%
аптайма; текущая цена и обязательство предупредить об изменении заранее; как
закрыть аккаунт.

Ссылки — в футере лендинга, строкой под кнопкой регистрации и в `sitemap.xml`.
Писать простым языком, а не юридическим.

## Грабли, на которые уже наступили

| Проблема | Симптом | Решение |
|---|---|---|
| `ro-RO` вместо `ro-MD` | Цена показывается как «850,00 MDL» вместо «850,00 L» | Всегда региональный тег `-MD` |
| Язык в cookie, а не в URL | Поисковик видит одну версию сайта вместо двух | Отдельные роуты `/ro` и `/ru` |
| `output: 'standalone'` ломает Vercel | ENOENT на `next-server.js.nft.json` | Не включать standalone, когда `process.env.VERCEL === '1'` |
| Redux store в модульной области | Кеш одной компании утекает в первый рендер другой | Store создаётся ленивым инициализатором `useState` в провайдере |
| Store в `useRef` | React 19: «Cannot access refs during render» | Тот же ленивый `useState` |
| `useDispatch.withTypes` в серверном бандле | Сборка падает: «withTypes is not a function» | `'use client'` в `shared/store/hooks.ts` |
| `Date.now()` в компоненте | React 19: «Cannot call impure function during render» | Часы читает роут и передаёт значение пропсом |
| `eslint-plugin-boundaries` и резолвер `next` | «typescript with invalid interface loaded as resolver» | Слои проверяются `no-restricted-imports` по тексту импорта |
| ESLint 10 и `typescript-eslint@8` | «scopeManager.addGlobals is not a function» | ESLint зафиксирован на 9.x |
| `middleware.ts` в Next 16 | Предупреждение об устаревшей конвенции | Файл называется `src/proxy.ts` |
| Сегмент `store` в steiger | «segment name should describe purpose» | Исключение с объяснением в `steiger.config.ts` |
| `fsd/insignificant-slice` на каркасе | Советует удалить только что созданные слайсы | Правило выключено: это эвристика, а не корректность |
